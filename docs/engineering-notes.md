# Mynote 工程沉淀

这份文档记录从 Mynote 维护与回归修复中保留下来的工程约定。版本变更清单见 [`CHANGELOG.md`](../CHANGELOG.md)；首页、编辑器、导出和视觉材质规范见 [`mynote-visual-language.md`](./mynote-visual-language.md)。

## 页面与静态资源

- Mynote 是无需生产构建的静态 HTML 应用。`index.html` 负责启动页，`Moment.html` 按顺序加载本地脚本；脚本顺序是运行时依赖的一部分，不要只移动文件而忽略页面引用。
- 新增或改名静态资源时，一并检查 `Moment.html`、`index.html`、`sw.js` 的引用与预缓存清单。改版时同步更新资源查询串、Service Worker 缓存名和应用版本，并运行 `npm run verify`。
- Service Worker 只缓存同源应用资源。Google 登录/Drive、天气和链接元数据仍是联网服务；离线能力是“已缓存后的本地编辑与存储”，不代表在线集成也能离线。

## Markdown 与内容安全

- Markdown 的代码示例不是待改写的普通文本。扩展语法扫描前先保护围栏代码、行内代码、HTML 标签和链接目标；转换后恢复原文，避免高亮、公式或自定义标记破坏代码、属性和 URL。
- 仅对受支持的 Markdown 扩展做转换；历史上已停用的短码或自定义语法应原样保留，不要在读取、摘要、保存或导出时静默改写旧笔记。
- Markdown 生成 HTML 后必须经过净化。DOMPurify 不可用时失败关闭或转义不可信内容；链接协议必须过滤，不能让导入内容或导出卡片执行脚本。
- 提示块、公式、双链、脚注等扩展应在编辑器、预览、摘要、导出及搜索路径间保持一致。处理嵌套内容时避开代码块；双链导航前先 flush 当前笔记的自动保存。

## 编辑器状态与保存时序

- 常规编辑器正文是单一 `contentEditable` DOM 流；可选的独立滚动模式则由不可编辑的外层正文容器和左右两个独立 `contenteditable` 列宿主承载输入。结构化笔记块与 DOM 顺序共同决定保存和导出；格式转换尽量局部更新并恢复所在列的选区/光标，跨列焦点切换不能误触发失焦渲染。
- 长标题可以从短标题布局升级为长标题滚动布局，但不要在输入过程中反复切换。IME 组合输入、移动 Safari 光标测量、软键盘视口 resize/scroll 都要单独考虑；关闭编辑器前先提交标题并 flush 自动保存。
- 对待办、链接和折叠提示等可交互 Markdown，保留语义元素、键盘焦点与触控尺寸；在委托事件中排除链接、按钮、输入框及 `summary`，避免把用户点击误当成进入编辑。
- DOM 格式化或命令会替换块节点时，先记录 `{ blockId, column, offset }` 光标描述；用 `Selection.focus`（而不是 `Range.end`）取得反向选区的焦点位置，并在新 DOM 挂载后定位正确的可编辑宿主再恢复光标。独立列不能对不可编辑的外层容器直接执行 `focus()`。
- 斜杠命令只在活动块、列和偏移仍能验证出原始 token 时删除触发文本；链接 URL 中的斜杠、音乐输入框中的 URL 不应启动命令。执行命令前取消尚未提交的普通输入快照，避免旧定时器把命令后的状态再次压入撤销栈。
- 独立双栏历史项同时保存文档和列布局；撤销/重做时按块 ID 重建内容顺序，再恢复列成员、模式与选区。插入、删除或移动块后都要重新规范化左右列边界，确保保存、恢复和导出仍是统一的左至右顺序。

## 本地数据、附件与备份

- 本地保存要能容忍单一存储层失败：保留同步的 localStorage 草稿兜底，再写 IndexedDB；恢复/合并完成后立即刷新基线，避免旧状态随后覆盖新数据。
- 页面隐藏或关闭前处理尚未完成的防抖保存。附件按笔记实际引用关系收集，识别图片类型时优先看文件魔数，而不是只相信扩展名；未知或损坏的单个附件不应让整份恢复失败。
- ZIP 导入先做大小、路径、中央目录/本地文件头、记录 ID、类型和字段白名单校验，再提交数据。保留旧备份格式兼容，但不要因为兼容而放宽危险路径、危险协议或超大声明的拒绝规则。
- 大附件打包采用流式处理和 ZIP Worker；Worker 不可用时走受控的主线程回退。Drive 上传使用 resumable 流程并明确区分授权、HTTP、网络和损坏响应错误。

## 导出与响应式界面

- HTML 与 PDF 从当前编辑器 DOM/CSS 快照导出，避免为图文卡、画廊、音乐、附件和待办维护多份近似渲染器；PDF 使用同一 HTML 进入浏览器打印流程。
- Markdown 始终从结构化笔记生成语义 Markdown，不包含编辑器 DOM/CSS 快照；导出可表示的文本、任务、图片和链接内容，但不承诺复刻卡片布局。HTML/PDF 快照应同步当前复选框状态、媒体说明和安全链接。
- 默认响应式编辑器保持同一正文流：大屏用 CSS 双栏书页排版，原子媒体卡片跨栏；窄屏手机横屏维持单栏。长表格和代码块在窄屏内横向滚动，不应造成整页溢出。
- 可选的双栏独立滚动模式默认关闭，入口在编辑器“更多”面板；左右两栏分别是实际编辑宿主，并各自滚动；外层正文只负责 React 事件委托与解析。保存、撤销/重做和导出须按左至右顺序扁平化；媒体卡、表格、代码、待办、输入法、粘贴与斜杠命令均要适配列宿主；手机窄横屏回退为单栏。
- 首页窄屏竖屏保留时间线列表；手机横屏与平板使用三列卡片，1280px 起宽桌面四列。玻璃材质按 overlay/content/control 分层，适配明暗主题、减少透明效果和无 `backdrop-filter` 环境；不以投影、高光、提亮或辉光装饰卡片。

## 回归检查

- `npm run verify` 检查页面脚本顺序、本地引用、版本串、模块声明和设计令牌。
- `npm test` 覆盖存储/备份校验、Markdown、安全协议、导出、预览及结构回归。
- `npm run check` 组合静态校验、单元测试、编辑器响应式浏览器测试和玻璃视觉矩阵。更新视觉基线前，先审阅界面变化并确认新的截图是预期结果。
- `npm run test:browser:markdown` 是独立的 Markdown 浏览器视觉回归；改动扩展语法、代码保护、主题排版或双链交互时应一并运行。
- `npm run test:browser:responsive` 覆盖响应式布局与双栏独立滚动的两个实际编辑宿主、独立滚动及顺序解析。
